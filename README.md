# FANBOX まとめて保存 — 無料更新版

Chromeウェブストアの登録・料金は不要です。現在はGitHubまたは更新ZIPから、管理画面で更新する方式です。ストアへの自動申請は停止しています。

v1.2.1から、公開ソースを使った「最新版に更新」が標準です。更新先が設定済みなら、フォルダ・ZIP・トークンの入力なしで確認・適用できます。Chromeが保存先の書き込み許可を再確認する場合だけ許可してください。取得対象にはFANBOXに直接添付された動画・音声も含みます。外部サービスの埋め込みは本体を取得せず、リンク情報を本文に残します。

v1.2.0では、投稿フォルダ・画像・添付ファイル・ZIP展開ファイルに投稿タイトルを含めます。保存済み投稿は、スキップ／再ダウンロード／中止を確認し、その実行中の残りにも同じ選択を適用できます。旧形式を再保存した場合、旧名ファイルは残します。

## 失敗分の再試行（v1.3.0）

- **旧版のログが残っていない場合**：「未完了・未取得分を再取得」を押します。同じ作品保存先を選び、以前と同じ支援先・金額条件で使ってください。保存完了記録とファイルのサイズ・更新時刻が一致する投稿は触らず、途中で止まった投稿と未取得投稿を保存します。過去の失敗だけを厳密に復元する機能ではありません。完了記録がない投稿は、ファイルがあっても再保存します。
- **この版以降の失敗**：作品保存先ごとにChromeのローカル領域へ記録し、「失敗分だけ再試行」で取り直せます。タブを閉じても残ります。Chromeの拡張機能削除・データ消去で履歴は消えます。履歴保存に失敗した場合は画面に通知します。
- **過去のテキストログがある場合**：失敗履歴を開いて「過去の失敗ログ.txtを取り込む」を使えます。「投稿 123：エラー内容」形式の行から投稿IDだけを抽出します（50MB・2万投稿まで）。本文・元のログ・URLは取り込みません。現在選択中・支援中の作者か確認してから再試行します。
- 再試行は投稿単位です。その投稿の画像・添付・本文を取り直します。成功した別の投稿を再ダウンロードすることはありません。一覧取得に失敗した支援先は一覧を再確認し、完了済みを飛ばします。金額条件や支援状況で取得できないものは履歴に残ります。
- 自分で停止した処理やタブ・PCの終了は失敗として記録できない場合があります。その場合は「未完了・未取得分を再取得」を使ってください。通常の「まとめて保存」では、これまでどおり保存済み投稿の再ダウンロードを確認します。

## 使い始める

[初回設定と更新方法](docs/初回設定.md)を確認してください。v1.0.xからの最初の切り替えだけは、ファイルの上書きとChromeの拡張機能再読み込みが必要です。その後は画面の「ツールの更新」から適用できます。

## 更新方法

- **ZIPから更新**：GitHub Releasesの更新ZIP、またはGitHubの「Code → Download ZIP」を保存し、管理画面の「更新ZIPを選んで適用」を押します。
- **最新版に更新**：公開リポジトリ kosh08/fanbox-downloader のmainから取得します。認証トークンは不要です。
- 初回だけ、作品の保存先とは別に、実際にChromeへ読み込んでいる拡張機能フォルダへの書き込みを許可します。
- 管理画面での明示操作による更新です。無人での自動更新は行いません。
- 更新ファイルのハッシュ・サイズ・権限を確認し、旧ファイルをバックアップして適用します。処理中のエラーは元に戻します。更新中のChrome終了・PC停止に対する完全な一括書き込み保証はありません。
- 書き換え後、読み込んでいるフォルダと一致することを確認し、拡張機能と管理画面を再読み込みします。設定・作品の保存先は維持します。

## 開発とリリース

1. ソースを修正し、extension/manifest.json のversionを上げます。画面の版表示も合わせます。
2. 以下のテストとビルドを行います。ビルドで生成される extension/update.json もコミットします。
3. GitHubで同じバージョンのリリース（例 v1.1.0）を公開すると、Actionsがテスト・更新ZIP生成・リリースへの添付を実行します。

```text
node --test extension/tests/*.test.mjs
python -m unittest discover -s scripts -p "test_*.py" -v
python scripts/build.py
```

Node.js 24以上、Python 3.10以上。追加パッケージ不要です。dist/ のZIPはmanifest.jsonが最上位にある更新用パッケージです。

GitHubへの追加接続権限を含むv1.1.0を最初に手動導入してください。以降も権限が変わる版は画面内で自動適用せず、手動導入を案内します。公開するのはソースだけで、ダウンロード作品や利用者の支援情報をリポジトリへ送信しません。

## 確認範囲

合成データでの投稿保存・ZIP展開、新旧FANBOX API形式、更新ZIPの読み取り・整合性確認・適用・ロールバックをテストしています。実アカウントのFANBOX投稿の取得は未検証です。GitHub Actionsは実行結果を確認してください。

scripts/publish.py とストア掲載関連文書は以前のストア案の資料として残しています。現在のワークフローから呼び出すことはありません。

# FANBOX まとめて保存 — 無料更新版

Chromeウェブストアの登録・料金は不要です。現在はGitHubまたは更新ZIPから、管理画面で更新する方式です。ストアへの自動申請は停止しています。

v1.2.1から、公開ソースを使った「最新版に更新」が標準です。更新先が設定済みなら、フォルダ・ZIP・トークンの入力なしで確認・適用できます。Chromeが保存先の書き込み許可を再確認する場合だけ許可してください。取得対象にはFANBOXに直接添付された動画・音声も含みます。外部サービスの埋め込みは本体を取得せず、リンク情報を本文に残します。

v1.2.0では、投稿フォルダ・画像・添付ファイル・ZIP展開ファイルに投稿タイトルを含めます。保存済み投稿は、スキップ／再ダウンロード／中止を確認し、その実行中の残りにも同じ選択を適用できます。旧形式を再保存した場合、旧名ファイルは残します。

## 更新分の保存とWindows展開連携（v1.5.0）

- 「保存方法」で「更新分だけ保存」「全件を確認して保存」を選べます。設定はChromeに保存します。支援先ごと・作品保存先ごとに、最終確認日時と最新確認投稿を記録して一覧に表示します。
- 更新分は新規投稿、編集された過去投稿、前回未完了の投稿です。既存の完了記録は初回に引き継ぎ、2回目から変更のない投稿の詳細取得と保存済みファイルの読み直しを省きます。初回や金額・無料投稿条件が変わったときは再確認します。編集検出のため投稿一覧の取得は毎回行います。更新日時が一覧にない投稿は詳細を再確認します。
- 更新された投稿は再保存し、同名ファイルを上書きします。以前の別名ファイルは残ります。「全件」では保存済みの投稿も確認対象に戻り、スキップ／再ダウンロードを選べます。過去ファイルを削除した場合の修復は「未完了・未取得分を再取得」で行ってください。
- その支援先の一覧を最後まで確認できたときだけ確認記録を進めます。停止・通信エラーで一覧確認が中断された場合は進めません。個別投稿の失敗は記録し、次回も対象にします。プレビューは確認記録を書き換えません。
- ChromeがDLL等のファイル作成を拒否するZIPや、ブラウザで圧縮方式に対応できないZIPは、元ZIPを保存して「Windowsでの展開待ち」にします。ダウンロードの失敗には数えず、残りの添付ファイル・投稿の保存を続けます。破損や容量不足などの実際のエラーは失敗として残します。
- Windows側ではPython 3.11以上で `python scripts/watch_unzip.py --root "D:\fanbox"` を起動しておきます。渡すのはローカルの作品保存先だけで、ネットワーク接続や新しいChrome権限は不要です。5秒ごとに待ちリストを読み、元の名前・階層で「ZIP名_展開」へ展開し、別ファイルでChromeに結果を返します。中身は起動せず、既存の展開先は上書きせず、識別子を付けた別名フォルダへ保存します。その別名フォルダも存在する場合とWindows側のエラーは「要確認」に表示します。
- Windowsツールを閉じている間は展開待ちが残ります。終了・PC再起動後は再度起動してください。Windows側のエラーの再試行は `--once --retry-errors` を追加して行えます。確認記録・展開リスト・結果は作品保存先の `.fanbox-state` 内に保存し、GitHubへ送りません。

## ZIPの展開エラーと再試行（v1.4.1）

ZIP名・失敗した内部ファイル名・処理段階・原因コードを表示します。破損・容量不足・圧縮方式・ファイル作成の制限を区別し、元ZIPは残します。エラーが残った投稿を完了扱いにはしません。

この版で保存したZIPには再試行用の記録を残します。「失敗分だけ再試行」「未完了・未取得分を再取得」では、投稿の更新日時・保存条件・取得元の識別ハッシュ・ファイルのサイズと更新時刻が一致すれば、そのZIPを再ダウンロードせずに展開を試します。破損を検出したZIP、更新された投稿や変更されたファイルは取り直します。通常の「まとめて保存」で再ダウンロードを選べば強制的に取得し直せます。記録がない旧版のZIPは自動流用しません。署名付きURLや認証情報は記録に保存しません。

UnityアプリなどのDLLを含むZIPは、Chromeのファイル保存制限で自動展開できない場合があります。元ZIPをエクスプローラーの「すべて展開」で展開してください。アプリの構成ファイルを拡張機能で平らに並べたり名前を変えると動作しなくなるため、この場合は元ZIPから元の名前・階層で展開する必要があります。拡張機能の更新でChromeの制限が解除されるわけではありません。

## 無料投稿のクリエイターを個別追加（v1.4.0）

保存設定の「無料投稿のクリエイターを追加」に、`https://creator-id.fanbox.cc/`、`https://www.fanbox.cc/@creator-id`、または `@creator-id` を入力して「個別追加」を押します。FANBOXで名前とIDを確認して追加します。未支援のクリエイターも取得でき、支援先一覧の読み直しや画面の再起動後も残ります。支援先の読み込みを先に行わなくても使えます（FANBOXには同じChromeでログインしてください）。

未支援の間は金額0円・無料投稿のみです。投稿ごとのフォルダ設定、タイトル付きのファイル名、本文・添付・ZIP展開、重複確認や再試行も既存の機能を使います。支援中のクリエイターと重複した場合は一覧を1件にまとめ、金額設定は支援額以下に制限します。「一覧から外す」で個別登録を解除できます。作品ファイルは削除しません。支援中の人は支援一覧に引き続き表示されます。

## 失敗分の再試行（v1.3.0）

- **旧版のログが残っていない場合**：「未完了・未取得分を再取得」を押します。同じ作品保存先を選び、以前と同じ支援先・金額条件で使ってください。保存完了記録とファイルのサイズ・更新時刻が一致する投稿は触らず、途中で止まった投稿と未取得投稿を保存します。過去の失敗だけを厳密に復元する機能ではありません。完了記録がない投稿は、ファイルがあっても再保存します。
- **この版以降の失敗**：作品保存先ごとにChromeのローカル領域へ記録し、「失敗分だけ再試行」で取り直せます。タブを閉じても残ります。Chromeの拡張機能削除・データ消去で履歴は消えます。履歴保存に失敗した場合は画面に通知します。
- **過去のテキストログがある場合**：失敗履歴を開いて「過去の失敗ログ.txtを取り込む」を使えます。「投稿 123：エラー内容」形式の行から投稿IDだけを抽出します（50MB・2万投稿まで）。本文・元のログ・URLは取り込みません。現在選択中・支援中の作者か確認してから再試行します。
- 再試行は投稿単位です。その投稿の画像・添付・本文を取り直します。成功した別の投稿を再ダウンロードすることはありません。一覧取得に失敗した支援先は一覧を再確認し、完了済みを飛ばします。金額条件や支援状況で取得できないものは履歴に残ります。
- 自分で停止した処理やタブ・PCの終了は失敗として記録できない場合があります。その場合は「未完了・未取得分を再取得」を使ってください。通常の「まとめて保存」では、これまでどおり保存済み投稿の再ダウンロードを確認します。

## 使い始める

[初回設定と更新方法](docs/初回設定.md)を確認してください。v1.0.xからの最初の切り替えだけは、ファイルの上書きとChromeの拡張機能再読み込みが必要です。その後は画面の「ツールの更新」から適用できます。

## 更新方法

- **ZIPから更新**：GitHub Releasesの更新ZIP、またはGitHubの「Code → Download ZIP」を保存し、管理画面の「更新ZIPを選んで適用」を押します。
- **最新版に更新**：公開リポジトリ kosh08/fanbox-downloader のmainから取得します。認証トークンは不要です。
- 初回だけ、作品の保存先とは別に、実際にChromeへ読み込んでいる拡張機能フォルダへの書き込みを許可します。
- 管理画面での明示操作による更新です。無人での自動更新は行いません。
- 更新ファイルのハッシュ・サイズ・権限を確認し、旧ファイルをバックアップして適用します。処理中のエラーは元に戻します。更新中のChrome終了・PC停止に対する完全な一括書き込み保証はありません。
- 書き換え後、読み込んでいるフォルダと一致することを確認し、拡張機能と管理画面を再読み込みします。設定・作品の保存先は維持します。

## 開発とリリース

1. ソースを修正し、extension/manifest.json のversionを上げます。画面の版表示も合わせます。
2. 以下のテストとビルドを行います。ビルドで生成される extension/update.json もコミットします。
3. GitHubで同じバージョンのリリース（例 v1.1.0）を公開すると、Actionsがテスト・更新ZIP生成・リリースへの添付を実行します。

```text
node --test extension/tests/*.test.mjs
python -m unittest discover -s scripts -p "test_*.py" -v
python scripts/build.py
```

Node.js 24以上、Python 3.10以上。追加パッケージ不要です。dist/ のZIPはmanifest.jsonが最上位にある更新用パッケージです。

GitHubへの追加接続権限を含むv1.1.0を最初に手動導入してください。以降も権限が変わる版は画面内で自動適用せず、手動導入を案内します。公開するのはソースだけで、ダウンロード作品や利用者の支援情報をリポジトリへ送信しません。

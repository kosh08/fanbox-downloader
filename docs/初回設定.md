# 自動更新を有効にする初回設定

この手順は最初の一回だけ行います。登録・認証が完了するまでは、今までの手動版を利用できます。

## 1. GitHubにリポジトリを作る

1. [GitHubの新規リポジトリ画面](https://github.com/new)を開きます。
2. 名前を `fanbox-downloader` などにします。公開・非公開は選べます。
3. この一式の中身をリポジトリの一番上に入れます。`extension/`、`scripts/`、`docs/`、`.github/workflows/` が並ぶ構成です。
4. `.github` は配布自動化の設定なので、アップロードから漏れないようにします。ブラウザで追加する場合は「Add file → Create new file」で `.github/workflows/check.yml` と `.github/workflows/release.yml` を作り、同梱ファイルの内容を入れる方法も使えます。
5. リポジトリの「Actions」で「Check extension」が成功することを確認します。

リポジトリが非公開の場合、公開用プライバシー説明は別途公開ページが必要です。利用するGitHubプランによってActionsの利用枠・公開ページの条件が異なるため、GitHubの管理画面で確認してください。

## 2. Chromeウェブストアの開発者登録

1. [Chromeウェブストア開発者ダッシュボード](https://chrome.google.com/webstore/devconsole/)を開きます。
2. Googleアカウントでログインし、画面の案内に沿って開発者登録を行います。登録・料金確認・本人確認・利用規約への同意はご本人で行ってください。
3. 公開・更新にはGoogleアカウントの2段階認証が必要です。
4. 新しいアイテムを作成し、同梱のストア登録用ZIP `FANBOX-Chrome-v1.0.1-store.zip` をアップロードします。リポジトリ全体のZIPはアップロードしません。
5. `ストア掲載文.md` を参考に説明文、権限の説明、スクリーンショットなどを登録します。ダッシュボードで追加の項目が求められる場合は記入してください。
6. `プライバシー.md` を公開Webページとしてホストし、そのURLを登録します。公開リポジトリのGitHub Pagesなどを利用できます。必要な公開者の連絡先もダッシュボードに登録します。
7. ストアの公開範囲は希望に合わせて選びます。リンクを知っている人への配布にしたい場合は、ダッシュボードで利用可能な限定公開の設定を確認してください。
8. 最初の版を手動で審査申請します。承認・公開されたら、ストア版をChromeにインストールします。

従来の手動インストール版はストア版に自動変換されません。保存済みの作品はそのまま残りますが、支援先設定やフォルダ許可はストア版で再設定が必要になる場合があります。同じダウンロードを二重に実行しないよう、切り替え後は旧版を無効にしてください。

## 3. 更新申請の認証を設定する

公式の[ChromeウェブストアAPI設定手順](https://developer.chrome.com/docs/webstore/using-api)に沿って、Google CloudプロジェクトでAPIを有効にし、OAuth認証情報と更新用のリフレッシュトークンを取得します。クライアントID、クライアントシークレット、リフレッシュトークンはチャットやソースファイルに貼らず、GitHub Secretsに直接登録してください。

OAuthの公開・テスト状態やトークンの有効期限によっては再認証が必要になるため、Googleの管理画面で状態を確認してください。代替のサービスアカウント認証へ移行する場合は、公式手順とスクリプトの両方を変更します。

GitHubリポジトリの「Settings → Secrets and variables → Actions」に以下を追加します。

**Secrets**（秘密の認証情報）:

| 名前 | 内容 |
| --- | --- |
| `CWS_CLIENT_ID` | OAuthクライアントID |
| `CWS_CLIENT_SECRET` | OAuthクライアントシークレット |
| `CWS_REFRESH_TOKEN` | chromewebstore権限を持つリフレッシュトークン |

**Variables**（配布先の設定）:

| 名前 | 内容 |
| --- | --- |
| `CWS_PUBLISHER_ID` | ストアの「Publisher → Settings」にある公開者ID |
| `CWS_EXTENSION_ID` | ストアに作成した拡張機能のID |
| `CWS_AUTO_PUBLISH` | 準備が完了したら `true`。未設定の間はストアへ送信しません |

## 4. 次回からの更新

1. 修正したファイルをリポジトリに入れます。
2. `extension/manifest.json` の `version` を上げます。例：`1.0.1` → `1.0.2`。画面の版表示も合わせて更新します。
3. 「Releases → Draft a new release」で新しいタグ `v1.0.2` を指定し、リリースを公開します。
4. 「Actions → Release and submit Chrome update」の結果を確認します。

テストが失敗するとストア申請へ進みません。認証設定がない間はZIPの生成・GitHubへの添付までです。認証後はAPIでアップロードし、審査申請します。審査通過後の公開とChromeへの配信には待ち時間があり、ストアが承認を保証するものではありません。

通信の失敗で申請が完了したか不明な場合は、自動で重複送信せず処理を止めます。ダッシュボードを確認してから再実行してください。
